# 위더스온 홈페이지 2차 수정 — 수정안(PPT v2) 반영 작업 명세

> **이 파일 사용법**
> - 이 파일은 프로젝트 루트에 `homepage_upgrade_v2_prompt.md`로 둔다. 수정안 PPT는 `docs/homepage_edit_v2.pptx`로 둔다. (실제 파일명이 다르면 0-2에서 실제 경로로 바꿔 쓴다.)
> - **이 문서는 수정안 v2 기준이다.** 이전 버전(v1) 명세나 PPT의 내용과 다르면 이 문서를 따른다.
> - 기준 문서: `CLAUDE.md`(마스터 가이드), `homepage_upgrade_prompt.md`(1차 고도화 명세). 1차 고도화 때 만든 구조(`site-config.js`, `layout.js`, `content.js`, `data-ck` / `data-img` / `gallery_items`)를 그대로 쓴다.
> - 요구사항은 아래에 모두 정리돼 있고 결정 사항도 확정됐다(0-4). **Phase 1 인터뷰는 하지 않고**, 진행 중 꼭 필요한 정보만 AskUserQuestion으로 짧게 묻는다.
> - **Phase 단위로 진행한다.** 각 Phase가 끝나면 스크린샷 확인 → 커밋 → 3~5줄 보고 → **사용자 확인 후 다음 Phase**로 간다.
> - 수정 문구는 이 문서에 적힌 그대로 쓴다. 표 안의 따옴표 안쪽 또는 코드블록이 최종 문구다. 임의로 다듬거나 지어내지 않는다.

### 0-3. ⚠️ 문구 수정 시 DB 덮어쓰기 주의 (가장 중요)
- 사이트는 로딩할 때 `site_content` 값으로 `data-ck` 요소의 `innerHTML`을 덮어쓴다. **관리자에서 이미 수정해 DB에 값이 있는 키는 HTML 기본 문구만 바꾸면 화면에 반영되지 않는다.**
- 그래서 각 Phase에서 바꾸는 키가 `site_content`에 저장돼 있는지 확인한다.
  - DB에 값이 있는 키는 HTML 기본값을 바꾸고, 같은 문구로 DB 값을 갱신하는 SQL을 `supabase/edit_v2_content.sql`에 모은다. 그다음 사용자에게 실행을 안내한다.
  - 기존 키 이름은 바꾸지 않는다. 구조가 바뀌는 곳(카드 추가, 단계 수 변경 등)은 새 키를 만들고, 쓰지 않게 된 키는 보고서에 남긴다. 삭제는 사용자 확인 후에 한다.
- 새로 생기는 모든 텍스트에는 `data-ck`, 이미지 슬롯에는 `data-img`를 붙인다. 네이밍 규칙은 `{페이지}.{섹션}_{항목}`이다.

### 0-4. 확정 사항 (사용자 결정 완료, 다시 묻지 않는다)
수정안 PPT와 다르게 확정된 내용이다. **PPT와 이 문서가 다르면 아래를 따른다.**

1. **'마인드 투데이' 띄어쓰기**: 사이트 전체에서 **'마인드 투데이'**(띄어 씀)로 통일한다. PPT의 '마인드투데이'도 모두 띄어 쓴다. 단, 로고 이미지·URL·영문 표기(Mind Today, mindtoday)는 그대로 둔다.
2. **'미디어' 메뉴 표시**: '기관 연결'과 같은 방식으로, hover·포커스·`/press` 진입 시 **'Mind Today'**로 표시한다(1-1).
3. **사업 페이지 히어로 eyebrow**: 새 메뉴명에 맞춘다 → '교육 운영' / '공연 기획' / '기관 연결 · Hoolter' / '미디어 · Mind Today' (1-1).
4. **훌터 페이지 Process 섹션 제목**: 슬라이드대로 한다. 제목 변경 지시가 없으므로 **'훌터가 연결하는 방법' 유지**, 본문만 핵심가치로 교체한다(5-1 H6·H7).
5. **문의 유형**: '신문 제휴 및 광고 문의' → **'언론사 제휴 및 광고 문의'**, '교육문의'·'공연문의' → **'교육 문의'·'공연 문의'**(띄어 씀) (1-8).
6. **마인드 투데이 Business 카드 제목**: 따옴표를 모두 뺀다(1-6).

- 우측 '문의하기' 버튼은 유지한다(`/#contact`).
- 드롭다운이 사라져도 `site-config.js`의 `children` 구조와 CLAUDE.md의 "하위 메뉴 추가 방법"은 그대로 둔다. 나중에 다시 추가할 수 있게 하기 위해서다. 각 섹션 `id`와 `scroll-margin-top`도 유지한다.
- **'기관 연결' Hoolter 표시**
  - 데스크톱: 마우스를 올리거나 키보드 포커스가 가면 메뉴 글자가 '기관 연결' → **'Hoolter'**로 바뀐다. 글자 폭이 달라 메뉴가 흔들리지 않도록 두 라벨을 겹쳐 두고 opacity/transform으로 교차 전환한다(`transition-all` 금지). 메뉴 폭은 긴 쪽 기준으로 고정한다.
  - `/platform` 페이지에 있을 때는 활성 상태로 **항상 'Hoolter'**로 표시한다.
  - 모바일 메뉴: hover가 없으므로 '기관 연결'로 표시하고, `/platform`에 있을 때만 'Hoolter'로 표시한다.
  - 접근성: 스크린리더용 이름은 '기관 연결 (Hoolter)'로 고정한다(`aria-label`). 라벨 전환은 `prefers-reduced-motion`이면 애니메이션 없이 즉시 바꾼다.
  - 구현은 `site-config.js` 항목에 `hoverLabel: 'Hoolter'`, `activeLabel: 'Hoolter'` 같은 옵션으로 넣는다. 다른 메뉴에도 같은 옵션을 붙일 수 있게 범용으로 만든다.

## Phase 2. 문의 폼 기능 (슬라이드 3, 4)

### 2-1. 개인정보처리방침 동의 (필수)
- '문의 보내기' 버튼 바로 위에 체크박스를 추가한다: **'개인정보처리방침에 동의합니다. (필수)'**
- '개인정보처리방침' 글자에 밑줄 링크(또는 옆에 '보기' 버튼)를 단다. 누르면 전문이 보이게 한다. 디자인에 맞게 모달이나 `/privacy` 페이지 중 하나를 고른다. 모달이면 Esc·바깥 클릭으로 닫히고 포커스가 모달 안에 머물게 한다.
- 체크하지 않으면 제출되지 않고, 체크박스 근처에 안내 문구를 보여준다.
- `consultations`에 `privacy_agreed boolean`, `privacy_agreed_at timestamptz`를 추가해 저장한다.
- **개인정보처리방침 전문**: `홈페이지 개인정보처리방침.txt`를 `privacy.html`(공통 레이아웃·헤더·푸터 적용, `noindex` 불필요, 고유 title/description)로 변환한다.
  - 원문 내용은 **바꾸지 않는다.** 제목·조항 번호·목록 구조만 HTML로 정리한다.
  - 원문에 빈칸·괄호 플레이스홀더(예: 시행일, 책임자 연락처)가 있으면 그대로 두고 보고한다.
  - **원문의 '수집 항목'에 첨부 파일(2-2)이 포함되는지 확인한다.** 이름·연락처·이메일·문의 내용·첨부 파일이 빠져 있으면 수정하지 말고 보고한다.

### 2-2. 파일 첨부 (한글·워드·PDF·이미지)
- '문의 내용' 아래에 첨부 입력을 추가한다. 드래그 앤 드롭과 클릭 선택을 모두 지원하고, 선택된 파일 목록과 개별 삭제를 보여준다.
- 허용 형식: `.hwp, .hwpx, .doc, .docx, .pdf, .jpg, .jpeg, .png, .webp`. 확장자와 MIME을 함께 검사하되, hwp는 MIME이 불안정하므로 확장자를 기준으로 한다.
- 제한: 파일당 10MB, 최대 3개 (상수로 두어 쉽게 바꿀 수 있게). 초과하면 즉시 안내한다.
- 저장: Supabase Storage **비공개(private) 버킷** `inquiry-attachments`, 경로는 `inquiries/{yyyy-mm}/{uuid}_{안전 처리된 원본명}`.
  - 정책: 익명 사용자는 **업로드(insert)만** 가능하다. 조회·목록·삭제는 로그인한 관리자만 가능하다.
  - `consultations`에 `attachments jsonb` 컬럼(`[{path, name, size, type}]`)을 추가한다.
- 관리자 상담 상세에 첨부 목록을 보여주고, **짧은 만료의 signed URL**로 다운로드하게 한다.
- 알림 메일(`/api/send-notification`)에는 첨부 파일명 목록과 "관리자 페이지에서 확인" 안내만 넣는다. 공개 링크는 넣지 않는다.
- 첨부 업로드가 실패해도 문의 본문은 저장하고, 첨부 실패만 안내하는 방식을 권장한다. 구현한 방식을 보고한다.
- SQL(컬럼 추가, 버킷, Storage 정책)은 주석을 단 `supabase/edit_v2_form.sql`로 만들고, "👤 사용자가 직접 할 일" 형식으로 안내한다.

## Phase 3. 공통 컴포넌트: 자동 슬라이드 갤러리 (슬라이드 8, 16, 22, 28)

4개 사업 페이지의 '관련 자료' 섹션(현재 "관련 자료를 준비하고 있습니다.")을 **사진이 자동으로 흐르는 슬라이드**로 바꾼다. 공통 컴포넌트 하나로 만들어 4개 페이지가 함께 쓴다. **사진은 나중에 관리자 화면에서 올린다**(초기 캡처 이미지는 만들지 않는다).

- **참고 레퍼런스:** https://moonda.kr/bravi. 먼저 이 페이지를 직접 확인한다. PPT 예시 스트립처럼 **가로로 이어진 사진 카드가 천천히 자동으로 흐르는** 형태다.
- 동작
  - 자동으로 흐르고 끝없이 이어진다. 마우스를 올리거나 포커스가 가면 멈춘다. 좌우 화살표나 스와이프로 직접 넘길 수도 있다.
  - 각 사진의 **왼쪽 하단 등 디자인에 맞는 위치에 짧은 설명 캡션**을 넣는다. 사진 하단에 그라데이션을 깔아 글자가 잘 보이게 한다.
  - 사진을 클릭하면 기존 라이트박스로 연다.
  - `prefers-reduced-motion` 사용자는 자동 재생을 끄고 수동 이동만 가능하게 한다.
  - 사진이 0장이면 섹션을 숨기거나 "자료 준비 중"을 보여준다(빈 회색 박스는 금지). 1~2장이면 무한 반복 없이 정적으로 배치한다.
- 데이터: 기존 `gallery_items`(page, image_url, caption, alt, sort_order, is_visible)를 그대로 쓴다. 캡션이 설명글로 나간다. 관리자 업로드·순서·숨김 흐름은 바꾸지 않는다.
- 이미지에 `loading="lazy"`를 쓰고 고정 비율(예: 4:3 또는 3:2)로 표시한다. 화면 밖 슬라이드는 늦게 불러온다.
- 각 페이지의 섹션 제목·서브카피 변경은 Phase 4·5에서 한다.

**Phase 3 완료 조건:** 테스트 이미지 5~6장으로 자동 재생·멈춤·수동 이동·캡션·라이트박스·모바일 스와이프·reduced-motion 확인 후 테스트 데이터 원복 → 커밋 → 보고 → 사용자 확인
