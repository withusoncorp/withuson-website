# 위더스온 홈페이지 3차 수정: 섹션 구조 정렬 · 핵심 가치 통일 · 교육/공연 보완

> **이 파일 사용법**
> - 프로젝트 루트에 `homepage_upgrade_v3_prompt.md`로 둔다. 기준 문서는 `CLAUDE.md`, `homepage_upgrade_prompt.md`(1차), `homepage_upgrade_v2_prompt.md`(2차)다. **이 문서와 앞 문서가 다르면 이 문서를 따른다.**
> - 참고 자료: 회사소개서 `소개서/index.html`(42p), 리플렛 `소개서/leaflet/leaflet.html`. 실제 경로가 다르면 파일명으로 찾는다. 페이지 번호(p05 등)는 회사소개서 `data-page` 값이다.
> - 문구는 **이 문서에 옮겨 둔 그대로** 쓴다. 표 안 문구와 코드블록이 최종 문구다. 임의로 다듬거나 지어내지 않는다.
> - 1차 때 만든 구조(`site-config.js`, `layout.js`, `content.js`, `data-ck` / `data-img` / `gallery_items`)를 그대로 쓴다.
> - 요구사항과 결정은 모두 확정됐다(0-3). **Phase 1 인터뷰는 하지 않고**, 진행 중 꼭 필요한 정보만 AskUserQuestion으로 짧게 묻는다.
> - **Phase 단위로 진행한다.** Phase마다 360 / 768 / 1280px 스크린샷 확인 → 커밋 → 3~5줄 보고 → **사용자 확인 후 다음 Phase**로 간다.
> - 점검 기준 화면: https://withuson-website-git-feature-multipage-withuson.vercel.app/ (2026-11-24)

## Phase 0. 작업 전 준비

### 0-1. 현황 파악 · DB 점검 (가장 중요)
1. 5개 페이지의 섹션 순서·`id`·배지·제목과 `data-ck` 키를 표로 정리한다.
2. **v2 수정 사항 중 화면에 반영되지 않은 항목이 있다**(1-4). `site_content`에 저장된 예전 값이 HTML 기본값을 덮어쓰는 문제로 보인다. 키 단위로 원인을 확인하고, DB 값을 갱신하는 SQL을 `supabase/edit_v3_content.sql`에 모아 사용자에게 실행을 안내한다.
3. 섹션 삭제·이동으로 쓰지 않게 되는 키는 **DB에서 지우지 않고** 보고서에 남긴다. 삭제는 사용자 확인 후에 한다.
4. `git commit`으로 백업한다.

### 0-2. 사업 페이지 공통 섹션 순서 (확정)
```
HERO → OVERVIEW → (훌터만) WHY HOOLTER → KEY FEATURES → CORE VALUES → FIELDS → (교육·공연만) GUIDE → RESOURCES → CTA
```
- **PROCESS 섹션은 4개 사업 페이지 모두에서 삭제한다.** REPORT 섹션은 만들지 않는다.
- 해당 사업에 없는 섹션은 건너뛴다(빈 섹션 금지). 배지는 영문 대문자로 통일한다.

### 0-4. 확정 사항 (다시 묻지 않는다)
1. 회사 소개 히어로 서브카피와 교육 운영 '현장 진행 사진' 테스트 데이터는 **사용자가 이미 처리했다.** 건드리지 않는다.
2. 교육 운영 HERO · OVERVIEW · KEY FEATURES는 **현재 문구 유지**.
3. 회사 소개 Business 카드의 제목·부제·태그 칩·이모지는 유지한다. 단, 훌터 카드 태그만 1-1대로 바꾼다.
4. 훌터 카드 '제공 서비스' 문구는 소개서 p05 원문(**'전문가'** 표현) 그대로 쓴다.
5. 사이트 전체에 'B2B'·'B2C' 표현을 남기지 않는다.
6. 강사 풀 상세(선발·검증 기준, 현장 운영 관리, 강사 등록 버튼)와 결과보고서 활용 섹션은 넣지 않는다.

### 1-1. Business 카드 4장: 소개서 p05 '주요 고객 · 제공 서비스' 표 추가

## Phase 2. 공통 작업

### 2-1. PROCESS 섹션 삭제
- 교육(`문의부터 결과 보고까지` 4단계), 공연(`공연 진행 과정` 5단계 + 결과물 칩), 훌터(`#process`), 미디어(`#process` id로 된 핵심 가치 섹션)에서 **PROCESS 섹션을 없앤다.**
  - 훌터 `#process`의 핵심 가치 → CORE VALUES로 이동(2-2), 섹션 제목 '훌터가 연결하는 방법' → WHY HOOLTER로 이동(5-2).
  - 미디어 `#process`는 내용이 핵심 가치이므로 id만 `values`로 바꾸고 CORE VALUES 위치로 옮긴다.
- 쓰지 않게 된 `proc-step` 컴포넌트·CSS는 다른 곳에서 쓰지 않으면 지운다. `data-ck` 키는 DB에 남기고 보고서에 목록으로 적는다.
- 회사 소개·내비·푸터에 `#process`로 가는 링크가 있으면 찾아서 정리한다.

### 2-2. 핵심 가치 블록 통일 (`ValuesBlock` 공통 컴포넌트)
**문제:** 같은 Together · Trust · Growth가 페이지마다 다른 배지(공연=KEY FEATURES, 훌터=PROCESS, 미디어=CORE VALUES, 교육=없음)와 다른 카드(`feat-card` / `val-card`, 번호 유무 다름)로 들어가 있다.

**구현**
- 4개 사업 페이지가 **같은 마크업·같은 CSS**의 컴포넌트 하나를 쓴다. 위치는 KEY FEATURES 다음(0-2).
- 섹션 `id="values"`, 배지 **CORE VALUES**, 부제 **이 사업이 구현하는 세 가지 운영 원칙** (모든 페이지 동일).
- 카드 3장 구성(위 → 아래): 아이콘 → 번호 `01·02·03` → 가치명(Together / Trust / Growth) → 회사 정의 한 줄(작은 글씨: 혼자가 아닌 함께 / 신뢰할 수 있는 연결 / 지속 가능한 성장) → 사업별 설명.
- 아이콘은 회사 소개 `#values` 카드와 **같은 아이콘**(Together=사람들, Trust=방패, Growth=상승 그래프)을 쓴다.
- 단계 연결선·화살표는 쓰지 않는다. 데스크톱 3열, 모바일 1열. 페이지 포인트 컬러는 아이콘 배경에만 쓴다(교육=brand, 공연=warm, 훌터=warm/brand, 미디어=forest).
- 회사 소개 `#values` 카드는 회사 차원의 정의라 문구는 그대로 두고, 카드 스타일(라운드·테두리·아이콘 크기)만 `ValuesBlock`과 같은 디자인 언어로 맞춘다.
- 키: 문구가 그대로인 페이지(공연·훌터·미디어)는 기존 키를 옮겨 쓰되, 키 이름이 섹션과 맞지 않으면(예: `performance.feature*`) 새 키 `{페이지}.values_*`를 만들고 같은 문구로 DB를 갱신한다. 옛 키는 보고서에 남긴다.

| 페이지 | 섹션 제목 | 설명 문구 |
|---|---|---|
| 교육 | 위더스온 교육의 핵심 가치 | 3-1 표 |
| 공연 | 위더스온 공연의 핵심 가치 | 현재 문구 유지 (Together: 사내 공간과 학교… / Trust: 이동 동선과 음량을… / Growth: 만족도 조사를 바탕으로…) |
| 훌터 | 훌터의 핵심 가치 | 현재 문구 유지 |
| 미디어 | 마인드 투데이 핵심 가치 | 현재 문구 유지 |

### 2-3. 운영 안내(GUIDE) 공통 컴포넌트
- 교육(3-3)과 공연(4-2)이 **같은 컴포넌트**를 쓴다. 소개서 p12·p30 레이아웃 기준.
- 구성: 배지 **GUIDE** → 제목 → 서브카피 → 카드 3장(아이콘 + 우측 상단 라벨 알약 + 제목 + 칩 + 설명) → 안내 띠(옅은 brand-50 배경 + 왼쪽 굵은 brand 강조선 + 아이콘 + 라벨·제목·설명 + 오른쪽 문의 버튼).
- 데스크톱 3열, 태블릿 1열(카드 가로형), 모바일 1열.

**Phase 2 완료 조건:** 4개 사업 페이지 섹션 순서가 0-3 매핑표와 일치 · PROCESS 0개 · `ValuesBlock` 4곳 동일 · 회사 소개 `#values`와 디자인 언어 일치 → 커밋 → 보고 → 사용자 확인
