# 위더스온 홈페이지 고도화 — 원페이지 → 5페이지 멀티페이지 전환

> 이 프롬프트는 프로젝트 루트의 `CLAUDE.md`(홈페이지 제작 마스터 가이드)와 현재 `index.html`을 기준으로 진행한다.
> 요구사항은 아래에 모두 확정되어 있으므로 **Phase 1 인터뷰는 생략**하고, 진행 중 꼭 필요한 정보만 AskUserQuestion으로 짧게 묻는다.
> 작업이 끝나면 맨 아래 **[보고 양식]**에 맞춰 보고한다.

## 0. 작업 전 현황 파악 (코드 수정 전에 먼저)

1. 프로젝트 전체 구조를 읽고 아래를 파악해 짧게 정리한다.
   - 관리자 대시보드 파일 위치·경로, 로그인/비밀번호 보호 방식
   - `site_content` 테이블 구조와 관리자 페이지에서 텍스트를 수정하는 방식 (`data-ck` 키 → `innerHTML` 치환)
   - `consultations` 테이블, `/api/send-notification` (Vercel 서버리스) 구조
   - `vercel.json` 유무, `brand_logo/`, `png/` 등 정적 자산 폴더
2. **현재 동작을 깨뜨리지 않는 것이 최우선.** 기존 `data-ck` 키 이름은 절대 바꾸지 않는다. (이미 관리자에서 수정한 문구가 DB에 저장돼 있음)
3. 작업 전 현재 상태를 git 커밋(또는 `backup/` 폴더 복사)해 되돌릴 수 있게 한다.

## 1. 사이트 구조 변경

### 1-1. 페이지 구성 (정적 HTML 멀티페이지 유지, 프레임워크 도입 금지)

| 상단 메뉴 | 파일 | URL | 내용 |
|---|---|---|---|
| About | `index.html` (기존 파일) | `/` | 현재 원페이지 그대로 (회사 소개) |
| 교육 프로그램 | `education.html` | `/education` | 위탁 교육·강사 매칭 사업 |
| 찾아가는 공연 | `performance.html` | `/performance` | 공연 사업 |
| 기관 탐색 서비스 | `platform.html` | `/platform` | 훌터(Hoolter) 플랫폼 |
| 온라인 언론사 | `press.html` | `/press` | 마인드 투데이 |

- `vercel.json`에 `"cleanUrls": true` 설정해 `.html` 없는 주소로 접근되게 한다.
- 로고 클릭 → `/`

### 1-2. 상단 메뉴

- 메뉴명(순서 고정): **About · 교육 프로그램 · 찾아가는 공연 · 기관 탐색 서비스 · 온라인 언론사**
- 우측 `문의하기` 버튼 유지 → `/#contact`
- **About 하위 메뉴(드롭다운):** Vision, Values, Business, Mission, Contact → 각각 `/#vision`, `/#values`, `/#business`, `/#mission`, `/#contact`
  - 데스크톱: hover + 키보드 focus 시 드롭다운 열림 (focus-within, Esc로 닫힘, aria-expanded 적용)
  - 다른 페이지에서 눌러도 메인으로 이동 후 해당 섹션으로 스크롤
  - 고정 헤더에 섹션 제목이 가리지 않도록 `scroll-margin-top` 적용
- **4개 사업 메뉴는 하위 메뉴 없이 시작** (단, 아래 1-3 구조로 언제든 추가 가능하게)
- 현재 페이지 메뉴는 활성 상태로 표시 (브랜드 컬러 밑줄 등)
- **모바일 메뉴 신설:** 현재는 모바일에서 메뉴가 아예 숨겨져 있음 → 햄버거 버튼 + 전체화면/드로어 메뉴, About 하위 메뉴는 아코디언으로

### 1-3. 메뉴 단일 설정 파일 (자연어 명령으로 하위 메뉴 즉시 추가용)

- 헤더·푸터·모바일 메뉴를 페이지마다 복붙하지 말고 **공통 파일 하나에서 렌더링**한다.
  - `assets/js/site-config.js` — 메뉴 구조(NAV 배열)만 담는 단일 소스
  - `assets/js/layout.js` — NAV를 읽어 헤더/모바일 메뉴/푸터 내비를 그림
- NAV 예시 구조:

```js
window.SITE_NAV = [
  { label: 'About', href: '/', children: [
      { label: 'Vision', href: '/#vision' },
      { label: 'Values', href: '/#values' },
      { label: 'Business', href: '/#business' },
      { label: 'Mission', href: '/#mission' },
      { label: 'Contact', href: '/#contact' },
  ]},
  { label: '교육 프로그램', href: '/education', children: [] },
  { label: '찾아가는 공연', href: '/performance', children: [] },
  { label: '기관 탐색 서비스', href: '/platform', children: [] },
  { label: '온라인 언론사', href: '/press', children: [] },
];
```

- `children`이 비어 있으면 드롭다운 화살표·패널이 표시되지 않고, 항목을 추가하면 자동으로 드롭다운이 생기도록 구현한다.
- 공통 Tailwind 설정(`tailwind.config`)과 공통 CSS(버튼, glass, reveal, blob 등)는 `assets/js/tailwind-config.js`, `assets/css/site.css`로 분리해 모든 페이지가 같은 파일을 불러오게 한다. Supabase 클라이언트 생성·`site_content` 로딩 로직도 `assets/js/content.js`로 분리한다.
- **CLAUDE.md에 "하위 메뉴 추가 방법" 섹션을 새로 추가**한다. 이후 사용자가
  "교육 프로그램에 '프로그램 목록', '강사 소개' 하위 메뉴 만들어줘"처럼 말하면 이 절차만 따라 바로 작업할 수 있어야 한다:
  1. `site-config.js`의 해당 메뉴 `children`에 항목 추가
  2. 하위 메뉴가 **같은 페이지 섹션**이면 → 해당 페이지에 `id` 있는 섹션 추가 (`/education#programs`)
     **별도 페이지**이면 → 사업 페이지 템플릿을 복제해 `education-xxx.html` 생성
  3. 새 텍스트에 `data-ck` 키, 새 이미지 슬롯에 `data-img` 키 부여 (네이밍 규칙 준수)
  4. 관리자 페이지 편집 목록에 새 키가 자동 노출되는지 확인
  5. 데스크톱/모바일 스크린샷 검증

## 2. 사업 페이지 4종 (공통 템플릿)

### 2-1. 페이지 구성 — 랜딩페이지형 사업 소개 + 관련 자료

모든 사업 페이지는 **같은 템플릿 구조**로 만들고, 섹션별 내용만 다르게 한다.

```
① 페이지 히어로      — 사업명(eyebrow), 헤드라인, 서브카피, 대표 오브제(3D 오브/아이소메트릭 SVG) 또는 대표 이미지 슬롯
② 사업 개요          — 핵심 메시지 + 짧은 설명
③ 핵심 특징 카드 3~4개 — 아이콘 + 제목 + 한 줄 설명
④ 도식 섹션          — 진행 프로세스/구조를 단계형 다이어그램(SVG·CSS)으로 (예: 문의 → 기획 → 운영 → 결과 보고)
⑤ 대상·분야          — 태그/칩 형태 (예: AI·디지털 교육, 경제 교육 …)
⑥ 관련 자료          — 이미지 중심 갤러리 (그리드 + 클릭 시 라이트박스, 캡션)
⑦ CTA                — "문의하기" → /#contact (외부 링크가 있는 사업은 해당 사이트로 가는 보조 버튼)
```

- 사업 소개는 **텍스트 + 도식 + 오브제 위주**, 관련 자료는 **이미지 위주**.
- 현재 About 페이지의 디자인 언어(브랜드 컬러 #A2AD24 계열, forest·warm 컬러, glass 카드, 3D 오브, 아이소메트릭 큐브, reveal 애니메이션)를 그대로 이어받는다. 페이지별로 포인트 컬러만 살짝 다르게 줄 수 있다 (예: 교육=brand, 공연=warm, 플랫폼=warm/brand, 언론사=forest).
- 갤러리에 이미지가 0개일 때는 섹션을 숨기거나 "자료 준비 중" 안내를 보여준다 (빈 회색 박스 금지).

### 2-2. 사업별 초안 카피 원칙

- 확인된 사실만 사용하고, 모르는 내용은 지어내지 말고 `[작성 예정]` 형태의 짧은 플레이스홀더 문구로 둔 뒤 보고서에 목록으로 정리한다.
- 확인된 사실:
  - **교육 프로그램:** 맞춤형 위탁 교육 및 강사 매칭. 현장 맞춤 교육 기획, 검증된 강사 풀 기반 위탁 운영·강사 파견. 분야: AI·디지털, 경제, 심리상담, 문화예술교육, 진로체험 (현재 index.html Business 카드 1 내용 활용)
  - **찾아가는 공연:** 공연 사업 (세부 내용 미정 → 플레이스홀더)
  - **기관 탐색 서비스:** 훌터(Hoolter) — 상담·발달센터·정신건강 전문가 연결 플랫폼. 슬로건 "고민을 훌훌 털어낼 전문가와 연결되는 곳". 외부 링크 hoolter.co.kr
  - **온라인 언론사:** 마인드 투데이 — 반드시 '신문사'가 아닌 **'언론사'**로 표기. 외부 링크 mindtoday.co.kr
- 교육·공연 프로그램과 훌터·마인드 투데이는 **운영상 별개**다. "프로그램 후 훌터로 연계" 같은 운영 연결 문구를 만들지 않는다. 사업 간 연결은 미션·의미 차원으로만 표현한다.

### 2-3. About 페이지(index.html) 조정

- Business 섹션: 현재 2개 카드 → **4개 사업 카드**로 확장하고 각 카드에 해당 사업 페이지 링크("자세히 보기") 추가. 기존 카드 1·2의 `data-ck` 키는 유지하고 새 카드만 새 키를 부여한다.
- 그 외 섹션·애니메이션·폼은 그대로 둔다.

### 2-4. 페이지별 SEO

- 각 페이지에 고유 `<title>`, `meta description`, `canonical`, OG 태그 작성 (도메인 https://www.withusoncorp.co.kr 기준).
- 기존 index.html의 사이트 인증 메타, GA/GTM 스크립트가 있다면 **모든 새 페이지에도 동일하게 포함**한다.
- `sitemap.xml`, `robots.txt` 생성/갱신.

## 3. 텍스트·이미지 편집 시스템

> 목표: 코드 수정 없이 **관리자 페이지에서 텍스트 수정 + 사진 업로드**를 하면 사이트에 바로 반영.

### 3-1. 텍스트 (기존 방식 확장)

- 기존 `site_content` + `data-ck` 방식을 그대로 모든 새 페이지에 적용한다.
- 키 네이밍 규칙: `{페이지}.{섹션}_{항목}` — 예: `education.hero_headline`, `performance.feature1_title`, `platform.process_step2_desc`
- 관리자 페이지 텍스트 편집 화면을 **페이지별 탭/그룹**(About / 교육 / 공연 / 기관 탐색 / 언론사)으로 정리해 키가 많아져도 찾기 쉽게 한다. 각 항목에는 현재 화면에 들어간 기본 문구를 보여준다.

### 3-2. 단일 이미지 슬롯 (히어로 이미지, 섹션 대표 사진 등)

- HTML에 `data-img="education.hero_image"` 같은 속성을 부여하고, 기본값은 오브제/플레이스홀더.
- 값(공개 URL)은 `site_content`에 같은 키로 저장 → 로딩 시 `src` 교체. (텍스트와 같은 테이블 사용, 키 접두어로 구분)
- 관리자 페이지에서 슬롯별 미리보기 + [이미지 교체] + [기본으로 되돌리기] + 대체 텍스트(alt) 입력.

### 3-3. 관련 자료 갤러리 (여러 장)

- 새 테이블 `gallery_items`:
  `id, page (education|performance|platform|press), image_url, storage_path, caption, alt, sort_order, is_visible, created_at`
- 관리자 페이지 "관련 자료" 탭: 페이지 선택 → 여러 장 드래그 업로드 → 캡션 입력 → 순서 변경(위/아래 또는 드래그) → 숨김/삭제.
- 사이트는 `is_visible = true`인 항목을 `sort_order` 순으로 표시.

### 3-4. 이미지 저장소

- **Supabase Storage** 공개 버킷 `site-media` 사용 (`pages/{page}/…`, `gallery/{page}/…` 경로).
- 업로드 전 브라우저에서 **리사이즈·압축**(긴 변 최대 1920px, WebP 우선) 처리 — 무료 용량(1GB) 보호와 로딩 속도 목적.
- 허용 형식: jpg, png, webp / 최대 용량 제한(예: 10MB) 안내.
- 사이트 이미지는 `loading="lazy"`, 고정 비율 컨테이너로 레이아웃 흔들림 방지.

### 3-5. 보안 (필수 점검)

- 0단계에서 확인한 관리자 인증 방식을 점검한다. **만약 관리자 페이지가 anon key + 화면 비밀번호만으로 `site_content`를 수정하고 있다면**, anon key는 공개 코드에 노출돼 있으므로 누구나 내용을 바꿀 수 있는 구조다. 이 경우:
  - Supabase Auth(관리자 이메일 계정 1개)로 로그인하도록 바꾸고,
  - `site_content`, `gallery_items` 쓰기와 `site-media` 업로드/삭제는 **로그인한 관리자만** 가능하도록 RLS·Storage 정책을 설정한다. 읽기는 누구나 가능.
  - 방식을 바꾸기 전에 사용자에게 1줄로 확인받는다.
- 필요한 SQL(테이블 생성, RLS 정책, 버킷·Storage 정책)은 **주석 달린 SQL 파일**(`supabase/upgrade.sql`)로 만들고, Supabase SQL Editor에서 실행하는 방법을 단계별로 안내한다. 사용자가 직접 해야 할 일은 CLAUDE.md의 "👤 사용자가 직접 할 일" 형식으로 쓴다.
- API 키(Resend, service role 등)는 코드에 직접 넣지 않는다. 새 비밀 값이 필요하면 Vercel 환경변수로 안내한다.

## 4. 디자인·품질 규칙 (CLAUDE.md 준수)

- 단일 기술 스택 유지: 정적 HTML + Tailwind CDN + Pretendard + Supabase JS
- `transition-all` 금지, Tailwind 기본 blue/indigo 금지, 모든 버튼·메뉴·드롭다운에 hover/focus-visible/active 상태
- 모바일 퍼스트 반응형 (360px / 768px / 1280px 확인)
- `prefers-reduced-motion` 사용자에게는 무한 애니메이션·스크롤 연동 효과 축소

## 5. 검증

1. 로컬 서버로 5개 페이지 모두 띄우고 **데스크톱·모바일 스크린샷**을 최소 2회 비교·수정
2. 체크리스트
   - [ ] 5개 상단 메뉴가 모든 페이지에서 동일하게 보이고 현재 페이지가 활성 표시됨
   - [ ] About 드롭다운 5개가 다른 페이지에서도 메인 해당 섹션으로 정확히 이동 (헤더에 안 가림)
   - [ ] 모바일 햄버거 메뉴 열기/닫기, 아코디언, Esc·바깥 클릭 닫기
   - [ ] `site-config.js`에 임시 하위 메뉴를 하나 넣으면 드롭다운이 자동 생성되는지 테스트 후 원복
   - [ ] 기존 `data-ck` 문구(관리자에서 수정한 값)가 그대로 반영됨
   - [ ] 관리자에서 새 페이지 텍스트 수정 → 사이트 반영
   - [ ] 관리자에서 단일 이미지 교체 / 갤러리 업로드·순서변경·숨김·삭제 → 사이트 반영
   - [ ] 로그아웃 상태(또는 anon)로는 쓰기·업로드가 거부됨
   - [ ] 문의 폼 제출 → `consultations` 저장 + 알림 메일 정상
   - [ ] 콘솔 에러 없음, 모든 페이지 title/description/OG 개별 적용
3. 확인 후 커밋. **배포(푸시)는 사용자 확인 후** 진행한다.
